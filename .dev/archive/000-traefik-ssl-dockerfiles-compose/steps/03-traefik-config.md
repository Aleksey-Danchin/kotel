# Step 03: Traefik Configuration Files

## Goal
Create Traefik static configuration and dynamic TLS configuration files that define HTTPS entrypoints, HTTP→HTTPS redirect, Docker provider for routing, and file provider for TLS certificates.

## Motivation
Traefik serves as the reverse proxy in the dev environment: it terminates TLS on `kotel.localhost`, redirects HTTP to HTTPS, and routes `/api/*` to the backend and `/*` to the frontend. The TLS certificates are generated by `mkcert` and stored in the system's mkcert CA directory — Traefik needs a dynamic config file to reference them inside the container.

## Type
infra

## Affected Area
- `infra/traefik/traefik.yml` (new — static configuration)
- `infra/traefik/dynamic/tls.yml` (new — dynamic TLS configuration)

## Dependencies
None

## Current Behavior
No Traefik configuration exists in the repository.

## Expected Behavior
Two configuration files exist that fully define Traefik's behavior for the dev environment.

## Specification

### `infra/traefik/traefik.yml` — Static Configuration

**Entrypoints:**
- `web`: listens on `:80`, configured to redirect all traffic to `websecure` entrypoint (HTTP→HTTPS).
- `websecure`: listens on `:443`, TLS enabled.

**Providers:**
- `docker`: enabled, `exposedByDefault: false` (services must opt-in via labels), `network: kotel-net` (the compose network name, to be created in step 05).
- `file`: `directory: /etc/traefik/dynamic`, `watch: true` (for TLS config).

**API / Dashboard:**
- `api.dashboard: false` — dashboard is not needed.

**Logging:**
- Set reasonable log level for dev (e.g., `log.level: WARN` or `ERROR`).

### `infra/traefik/dynamic/tls.yml` — Dynamic TLS Configuration

**TLS stores — default:**
- Default certificate:
  - `certFile: /certs/kotel.localhost.pem`
  - `keyFile: /certs/kotel.localhost-key.pem`

These paths are container-internal. The compose manifest will bind-mount the host directory `$(mkcert -CAROOT)/kotel/` to `/certs:ro` inside the Traefik container.

### Routing

Routing rules are NOT defined in these config files — they are defined via Docker labels on each service in the compose manifest (step 05). This keeps routing co-located with service definitions.

## Acceptance Criteria
1. `infra/traefik/traefik.yml` exists with two entrypoints (`web` on 80, `websecure` on 443).
2. HTTP→HTTPS redirect is configured on the `web` entrypoint.
3. Docker provider is enabled with `exposedByDefault: false`.
4. File provider points to `/etc/traefik/dynamic` directory.
5. Dashboard is disabled.
6. `infra/traefik/dynamic/tls.yml` exists with default TLS certificate pointing to `/certs/kotel.localhost.pem` and `/certs/kotel.localhost-key.pem`.
7. Both files are valid YAML.

## Verification Scenario
1. Validate YAML syntax: `python3 -c "import yaml; yaml.safe_load(open('infra/traefik/traefik.yml'))"` (or equivalent).
2. Inspect the files and confirm entrypoints, providers, and TLS references are correct.

## Testing
Manual verification only. Full integration test happens when the compose stack is started (step 05+06).

## Notes
- The compose network name used in the Docker provider config (`kotel-net`) must match the network defined in the compose manifest (step 05). If the name differs, update accordingly.
- Traefik v3 configuration format should be used (current stable as of 2026).
- The cert file paths (`/certs/...`) are container-internal paths. The actual host paths are managed by the dev-start script (step 06) and compose volumes (step 05).
