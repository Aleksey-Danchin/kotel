# Step 05: Create Users Resource in Backend

## Goal
Create a minimal NestJS `users` resource (via Nest CLI only) to expose `GET /api/users` and return seeded users from Prisma.

## Motivation
The task requires an explicit full chain check: frontend button -> React Query -> axios limiter -> backend controller/service -> Prisma -> DB -> response.

## Type
backend, feature

## Affected Area
`apps/backend/src/users/*` (generated by `npx nest g resource users` or equivalent), `apps/backend/src/app.module.ts`, Prisma integration files from previous step

## Dependencies
Depends on step 04

## Current Behavior
- Backend exposes only root hello route through `AppController`.
- No `/api/users` endpoint exists.
- No users module/service/controller bound to Prisma.

## Expected Behavior
- Backend contains CLI-generated users resource (not manually handcrafted from scratch).
- `GET /api/users` returns all users (100 from seed scenario), no pagination.
- Response excludes `login` and `passwordHash` due to global Prisma base omit configuration.

## Specification
- Generate resource using Nest utility only:
  - `npx nest g resource users` (REST transport, without unnecessary CRUD handlers if not needed)
- Keep implementation minimal:
  - only code needed for read path used in test scenario
  - remove unused generated operations if they are not part of required flow
- In `UsersService`, query Prisma user collection (`findMany`) and return list.
- In `UsersController`, map GET route to service method.
- Ensure module wiring in `AppModule` includes `UsersModule`.
- Do not add auth/guards/pagination in this step.

## Acceptance Criteria
1. Users resource exists and is created via Nest CLI generator.
2. `GET /api/users` responds with list of users from DB.
3. Endpoint returns full seeded set (100 users) without pagination.
4. `login` and `passwordHash` are not present in response payload.
5. Backend compiles and starts cleanly.

## Verification Scenario
1. Ensure DB is seeded (step 03 script).
2. Start backend.
3. Call `GET https://kotel.localhost/api/users`.
4. Verify HTTP 200 and array length 100.
5. Inspect one item and confirm omitted sensitive fields are absent.

## Testing
- Backend integration test for `GET /api/users` success and response shape.
- Manual curl/browser verification through Traefik endpoint.

## Notes
- Keep API shape simple and deterministic for frontend integration step.
