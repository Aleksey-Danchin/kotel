1) Нужно добавить в scripts prisma-migrate.sh. Скрипт должен использовать уже поднятый studio контейнер или поднять его ровно для выполнения действия миграции. Миграция должна проходить через контейнер studio. prisma миграция. Название файла миграции передается через скрипт.

Пример:
./scripts/prisma-migrate.sh create_user_table

2) Нужно настроить studio на проведение всех имеющихся миграций.

3) ./scripts/prisma-migrate.sh так же через studio container должен позаботится о  том, что будет сгенерирован новый код ./apps/prisma/client. Но это кажется происходит автоматически при создание миграции, так что только проверить.

4) Для проверки можно использовать непосредственно пример из 1го пункта.

5) Нужно чтобы после успешной и неуспешной миграции был переопределен текущий пользователь и/или файловые права на всю директорию prisma. Например `chown -R $USER:$USER ./prisma`. $USER - это должен быть текущий пользователь скрипта, в данном случае aleksey. Делать это нужно так же через контейнер studio чтобы не было проблем с sudo.

6) Нужно настроить backend. Нужно создать модуль для экспорта Prisma как NestJS модуля. Потом он будет использоваться в других модулях для получения доступа к prisma instance. Обрати внимание, то современный prisma требует adapter pg. Это часть prisma - так что в директори prisma нужно будет создать отдельный файл, который будет возвращаться уже prisma instance с подключенным адаптером. backend только им пользуется. Prisma service  в prisma module - это лишь обертка (псевдоним).

7) Нужно сделать файл seed для пользователей. Создай в prisma директиву для всех будущих сидов. Сейчас нужно настроить seed только для пользователей. Создай 100 пользователей. Пароль у всех `123` и имена и логины будут соответствовать порядковому номеру.

8) Сид не должен запускаться где-то автоматически. Только ручное управление. Для этого нужно будет в scripts добавить скрипт запуска seed также через studio. Этот скрипт должен будет очищать все таблицы до сида, а после запускать силами prisma seed файлы с моками.

9) Нужно провести сквозную проверку работы системы. Нужно на frontend добавить страницу users. На странице будет пустая таблица и кнопка "загрузить". При клике срабатывает стандартный сценарий:

button -> tanstack/query -> axiosLimitter -> axios -> GET: /api/users -> nestjs controller -> nestjs service -> prisma service -> prisma SELECT users -> и обратно.

Для теста нужно будет создать users ресурс в nestjs. Создавай только через утилиту `npx nest` или `nest`. Не нужно создавать ничего в ресурсе кроме того, что понадобится в тесте взаимосвязи.

Результатом должны быть ранее созданные seed пользователи. Вывести их а таблицу.

10) В backend для passwordHash нужно будет установить `npm install bcryptjs`

11) В Prisma base omit нужно прокинуть passwordHash и login.
