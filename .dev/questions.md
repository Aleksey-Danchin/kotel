## Q12 — Уточнение к Q8: точный backend URL для mobile в Android-эмуляторе

Для Android-эмулятора есть несколько рабочих схем, и от выбора зависит спецификация шагов:
- HTTP напрямую в backend контейнер (обычно `http://10.0.2.2:3000/api`) — проще сеть, но без traefik/TLS.
- HTTPS через traefik-домен (`https://kotel.localhost/api`) — ближе к web, но домен/сертификат в эмуляторе часто требуют отдельной настройки.

Вы в Q8 указали неуверенность и возможный real IP + host подмена. Нужен окончательный целевой вариант для текущего этапа.

**Варианты:**
- a) Зафиксировать простой dev-вариант: `http://10.0.2.2:3000/api` для mobile (без TLS и без `kotel.localhost`).
- b) Обязательно сохранить доступ именно через `https://kotel.localhost/api` и добавить нужную сетевую/SSL-конфигурацию.
- c) Использовать real host IP + порт backend/traefik (укажите точный формат URL).
- d) Другое: ___

**Ответ:** Использовать real host IP + порт backend/traefik с заголовком host kotel.localhost. Просто обратится к `https://kotel.localhost/api` нельзя, так как dns не сработает. `http://10.0.2.2:3000/api` лишает возможность пользоваться ssl, а это важный аспект даже во время тестирования. Гарантируется только что android и host в одной сети wifi.
