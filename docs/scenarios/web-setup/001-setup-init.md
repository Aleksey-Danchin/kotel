# Scenario 001: Первичная настройка сервера и создание root пользователя

**Client:** web  
**Automated test:** `apps/frontend/e2e/auth/setup-flow.spec.ts`

## Goal

Администратор выполняет первичную инициализацию сервера, проверяет блокировку повторной инициализации и затем логинится обычным OAuth-потоком.

## Preconditions

- Backend-сервер запущен и доступен.
- Сервер может быть как неинициализированным, так и уже инициализированным.

## Steps

1. Открыть страницу `/setup`.
2. Убедиться, что виден заголовок "Первичная настройка сервера".
3. Ввести URL сервера и нажать "Check availability".
4. Если сервер не инициализирован: заполнить форму "Создать root пользователя" и нажать "Инициализировать".
5. Если сервер уже инициализирован: убедиться, что показано сообщение о переходе к обычному логину.
6. Выполнить повторный `POST /api/setup/init` с другими данными и убедиться, что ответ `403 Forbidden`.
7. Перейти на `/session-test`, добавить сервер через OAuth popup.
8. Убедиться, что карточка сервера появилась, а root-пользователь может авторизоваться.

## Notes

- Инициализация setup одноразовая: после создания root `GET /api/setup/status` возвращает `{ "available": false }`.
- Связанная документация: `docs/auth/implementation-decisions.md` (решение 11, first-run setup).
